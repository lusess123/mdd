# MMD 开源项目需求

## 背景

当前 MMD 依赖 Cookiy 内部的数据库、认证、请求和路由模块，外部项目无法直接使用。需要提取通用能力并发布为公共 npm 包，同时提供官网、文档、Playground 和可运行 Demo。

## 产品定位

MMD 是可扩展的元数据驱动开发工具。开发者定义模型和视图后，即可获得查询、筛选、详情、新建、编辑和删除能力，并可扩展字段、操作和页面区域。

## 目标

- 将共享协议、服务端引擎和前端渲染器拆分为独立 npm 包。
- 允许使用方注入 Prisma Client、请求上下文和业务扩展。
- 为 API、认证、路由和错误处理提供开箱即用的默认实现，同时允许覆盖。
- 提供中英文界面、完整文档、在线体验和可独立运行的示例。
- 通过本地和 Cloudflare 部署验证 MMD 可在 Cookiy 之外运行。

## 包结构

```text
mmd-contracts
mmd-engine
mmd-renderer
```

- `mmd-contracts`：模型、视图、字典、请求响应和错误协议。
- `mmd-engine`：基于 Prisma 执行元数据读取、查询、增删改和自定义操作。
- `mmd-renderer`：基于 React 和 Ant Design 渲染列表、详情、表单和扩展组件。

```text
mmd-engine ─────→ mmd-contracts
mmd-renderer ───→ mmd-contracts
```

`mmd-contracts` 已确认；`mmd-engine` 和 `mmd-renderer` 暂定。2026-07-14 查询时三个名称均未注册，正式发布前需再次确认并尽快发布占位版本。

## 核心能力

### 共享协议

- 定义模型、字段、视图、字典和扩展协议。
- 定义查询、分页、筛选、增删改、元数据和错误类型。
- 提供通用校验，不包含数据库、服务端框架或 UI 逻辑。

### 服务端引擎

- 注册模型、视图、字典和自定义操作。
- 注入一个或多个 Prisma Client。
- 提供元数据、列表、单条、新增、修改和删除能力。
- 支持字段读写限制、数据权限、操作权限及用户、租户等请求上下文。
- 不创建数据库连接，不读取业务环境变量，不依赖 Cookiy 内部包。
- 不绑定 HTTP 框架；示例后端使用 Hono。

### 前端渲染器

- 提供 Provider 和 MMD 页面组件。
- 支持列表、分页、搜索、筛选、详情、新建、编辑和删除。
- 支持注册自定义字段、自定义操作和页面插槽。
- API、认证、路由和错误处理均可配置，并提供零配置默认值：
  - API 前缀：`/api`。
  - 认证：匿名访问，请求携带同源 Cookie。
  - 路由：Hash 路由。
  - 错误处理：内置错误提示与反馈。
- 支持中文和英文。默认按浏览器语言选择，也可通过 `locale` 和 `messages` 覆盖语言及文案。
- 不依赖 Cookiy 的登录、请求、路由或工具包。

## 扩展能力

### 自定义字段

字段可分别定义列表和详情展示、表单编辑、查询条件、校验规则及数据转换。首期示例包括图片、用户选择、标签、富文本、JSON 和金额。

### 自定义操作

统一使用 `Action` 描述页面顶部、行内、批量、详情、表单及字段快捷操作。支持权限、禁用条件、上下文、二次确认、加载状态、结果反馈，以及执行后的刷新、跳转或弹窗。

首期示例包括审核、批量启用、导出、复制记录、自定义弹窗和外部跳转。

### 页面插槽

允许在以下区域插入自定义 React 内容：

```text
pageHeader
toolbarBefore
toolbarAfter
tableBefore
tableAfter
detailBefore
detailAfter
formBefore
formAfter
```

## 官网、文档与 Playground

官网、文档和 Playground 使用同一前端项目，包含首页、快速开始、使用指南、API 文档、示例、Playground、更新日志和 GitHub 入口。

首页需要展示产品定位、真实 MMD 界面、模型与页面的对应关系、三个包的职责、最短安装方式及主要入口。整体采用紧凑的深色开发者工具风格，以真实交互、代码和运行数据为主。

文档需要覆盖：

- 从安装、模型定义、Prisma 配置、HTTP API 到 React 渲染的最小闭环。
- 模型、视图、字典、查询、权限、自定义字段、Action、插槽、多数据库、认证、国际化、错误处理和迁移。
- 按三个包组织的 API Reference，包含类型、参数、返回值、错误、示例和源码链接。
- Demo HTTP API 的请求参数、响应、错误码和在线调试入口。

TypeScript API 文档尽量从源码生成，避免文档与实现不一致。

Playground 首期提供 Basic CRUD、Custom Fields、Custom Actions、Page Slots、Permissions 和 Multiple Databases。每个场景同时展示运行结果、配置、前后端代码、请求响应、操作日志和 GitHub 示例地址。

## Demo 与部署

### 本地开发

- 使用 Bun 安装依赖并运行项目。
- Demo 后端使用 Hono。
- 官网和 Demo 前端使用 Next.js，并启用 `output: 'export'` 生成静态文件。
- Provider 零配置默认请求同源 `/api`，并通过配置测试验证默认值。
- Demo 本地注入 `http://localhost:8787/api`，生产构建注入 `https://mmd-api.zyking.xyz/api`。

### 云端部署

后续部署到 Cloudflare：

- 官网域名：`mmd.zyking.xyz`。
- API 域名：`mmd-api.zyking.xyz`。

```text
Cloudflare Pages
└── 官网、文档、Playground 和静态 Demo 前端
          │
          ▼ /api
Cloudflare Workers
└── Hono Demo API
    ├── mmd-engine
    ├── 模型、权限和操作注册
    └── Prisma Client
          │
          ▼
在线 Demo 数据库
```

`mmd-engine` 只依赖注入的 Prisma Client，不绑定 Cloudflare 或具体数据库。

示例模型包括：

- `User`：用户选择、状态和角色权限。
- `Product`：图片、金额、标签和自定义字段。
- `Order`：审核、批量处理和自定义操作。

数据保护要求：密钥保存于 Cloudflare Secrets；限制写入范围和请求频率；隔离访客数据或仅允许修改本人创建的数据；定时清理或恢复示例数据。

## 发布与迁移

- 发布到 npmjs.com，使用无 scope 公共包名。
- 包内不得包含 `workspace:*`、Cookiy 或 Vovey 私有依赖。
- Prisma、React、React DOM 和 Ant Design 等宿主依赖使用 `peerDependencies`。
- 先发布 beta，验证后发布正式版本。
- 通用协议迁入 `mmd-contracts`，通用 Prisma 操作迁入 `mmd-engine`，通用 React 页面迁入 `mmd-renderer`。
- NestJS Controller、Cookiy 权限和具体 Prisma Client 留在业务仓库。
- Cookiy 请求、认证、路由和业务组件改为外部注入。
- 保留旧导出路径作为迁移期兼容层。

## 首期范围

- 三个 npm 包的基础能力。
- 官网、快速开始、API Reference 和中英文界面。
- Bun 本地开发环境、Hono Demo API 和 Next.js 静态前端。
- User、Product、Order 三组模型及完整 CRUD。
- 权限、自定义字段、自定义操作和页面插槽。
- 在线 Playground、Cloudflare 部署和 Demo 数据保护。

## 验收标准

- 仓库外项目可通过 npm 安装三个包，包内无私有依赖和 `workspace:*`。
- 使用方可注入 Prisma Client，服务端引擎不绑定 NestJS。
- Hono Demo API 可在本地运行，并可部署到 Cloudflare Workers。
- Next.js 前端可静态导出并部署到 Cloudflare Pages。
- 零配置时可通过 `/api`、匿名同源 Cookie、Hash 路由和内置错误反馈完成完整 CRUD。
- API、认证、路由、错误处理、`locale` 和 `messages` 均可覆盖。
- 中文、英文可按浏览器语言自动切换，显式配置可覆盖默认行为。
- 自定义字段、Action 和页面插槽均有文档、代码和在线 Demo。
- Playground 可查看前后端代码、请求响应和操作日志。
- Cookiy 现有 MMD 功能回归通过。
- 类型声明、npm 包内容和公开文档完整。
