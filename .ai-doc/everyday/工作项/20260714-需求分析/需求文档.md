# MMD 开源项目需求

## 定位

MMD 是元数据驱动的全栈管理工具。开发者定义模型、字段和操作后，即可获得安全的数据 API 与 React 管理界面，并可替换数据库、字段组件和业务操作。

## 交付物

- `mmd-contracts`：模型、字段、视图、字典、Action 和请求响应协议。
- `mmd-engine`：模型注册、元数据、查询、分页、过滤、增删改和自定义操作。
- `mmd-renderer`：Provider、列表、搜索、详情、表单、字段注册、操作注册和页面插槽。
- Hono Demo API：通用 MMD 接口、Product REST 别名、OpenAPI 与可视化 API 文档。
- Next.js 静态网站：中英文官网、文档、示例和可操作 Playground。
- 可复制示例：基础前后端、自定义字段、自定义操作和 Provider 覆盖。

## 核心流程

```text
ModelDefinition
    ├── mmd-engine ── MmdDataAdapter ── Neon PostgreSQL
    └── mmd-renderer ── HTTP MMD API ── Hono
```

服务端引擎不绑定 Hono、Prisma 或 Cloudflare；数据库通过六个稳定操作的 `MmdDataAdapter` 注入。Demo 使用 Prisma + Neon 实现，未配置 `DATABASE_URL` 时回退到内存适配器。

## 功能要求

### 通用能力

- 根据模型自动生成列表、搜索、详情、新建和编辑视图。
- 仅允许访问模型已声明字段，写入主键、只读字段或未知字段时直接拒绝请求。
- 支持分页、排序及 `eq`、`contains`、`in`、`gte`、`lte` 过滤。
- Action 必须先在模型声明并在服务端注册处理器。
- API 错误统一返回 `{ error: { code, message, details? } }`。

### 前端配置

`MmdProvider` 不配置时提供以下默认实现：

- API：原生 `fetch`，地址为同源 `/api`，超时 10 秒。
- 认证：匿名访问，携带同源 Cookie。
- 路由：Hash 路由。
- 错误：统一处理超时、网络和 API 错误，并显示反馈。
- 国际化：内置 `zh-CN`、`en-US`，按浏览器语言选择。

使用方可覆盖 API 地址、路径、请求函数、Token/Header、路由、错误回调、语言和文案。线上跨域 Demo 使用 `credentials: "include"`。

### 扩展示例

- 自定义字段：`inventory-meter` 在列表中显示库存进度，在表单中使用数字输入框。
- 内置字段示例：图片、金额、标签、状态、文本、数字和日期时间。
- 自定义操作：发布、归档、复制；支持行操作、批量操作、显示条件、确认和刷新。
- 后端示例：Hono 路由调用 `mmd-engine`，Prisma 适配器负责 Neon 数据访问。
- 页面插槽：视图、容器、加载、错误和空状态前后均可注入 React 内容。

## Demo 与数据

首期以 Product 完成端到端验证，包含 CRUD、搜索、状态、库存和三种业务操作。线上数据存储在 Neon PostgreSQL；服务端通过 HttpOnly Cookie `mmd_session` 或 `X-MMD-Session` 隔离访客数据，并为新会话写入种子数据。

## 官网与推广

官网采用手绘漫画风格，首页直接说明价值、展示真实数据界面和最短运行命令。文档覆盖快速开始、通用 API、扩展开发和部署；示例页链接仓库内可复制代码；Playground 展示真实请求、响应和对应前后端代码。

## 技术与部署

- 本地运行时：Bun。
- API：Hono，部署到 Cloudflare Workers。
- 前端：Next.js `output: "export"`，部署到 Cloudflare Workers Static Assets。
- 数据库：Neon PostgreSQL，Prisma Client 使用 Neon Adapter。
- 官网：`mmd.zyking.xyz`。
- API：`mmd-api.zyking.xyz`。
- 线上 API 文档：`mmd-api.zyking.xyz/docs`。
- 密钥只保存在 GitHub Secrets 和 Cloudflare Secrets，不进入仓库。

## 包名与发布

公共包名使用 `mmd-contracts`、`mmd-engine`、`mmd-renderer`。2026-07-14 查询时三个名称均未注册；npm 发布前必须再次检查。发布包不得包含 `workspace:*` 或私有依赖，React、React DOM、Ant Design 等宿主库使用 `peerDependencies`。先发布 beta，再升级稳定版本。

## 首期不做

- 不迁移 Cookiy 专用 Controller、权限和业务组件。
- 不把引擎绑定到特定 ORM 或 Web 框架。
- 不在公开 Demo 中提供管理员或跨会话数据访问。
- 不在本阶段承诺复杂关系字段、多数据库事务或完整 RBAC。

## 验收标准

- 三个包在仓库外无 Cookiy/Vovey 私有依赖，可独立类型检查与测试。
- Hono API 本地可运行，通用元数据、查询、保存、删除和 Action 接口可用。
- Next.js 可静态构建，Playground 使用 `mmd-renderer` 调用真实 API。
- Product CRUD、自定义库存字段、发布、归档和复制均可操作。
- API、认证、路由、错误处理和中英文文案均可覆盖；不配置时默认实现可工作。
- Neon 数据按会话隔离，未提供数据库地址时可使用内存适配器。
- 官网、API、文档、代码示例和部署域名保持一致。
- npm 发布前重新检查包名并确认产物不含工作区或私有依赖。
