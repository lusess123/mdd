# 技术方案

## 模块边界

```text
mmd-contracts
    ↑                 ↑
mmd-engine       mmd-renderer
    ↑                 ↑
MmdDataAdapter   MMD HTTP API
    ↑                 ↑
Prisma + Neon       Hono
```

- `mmd-contracts` 仅包含可序列化协议和兼容别名。
- `mmd-engine` 校验模型、字段、过滤条件和写入内容，不持有数据库连接。
- `mmd-renderer` 根据元数据渲染 React 界面，通过 `MmdClient` 访问服务端。
- Demo API 负责 Hono 路由、Zod 校验、运行时创建和错误映射。

## 数据访问

`MmdDataAdapter` 只定义 `findMany`、`count`、`findOne`、`create`、`update`、`remove`。Neon 实现使用 Prisma Client + `@prisma/adapter-neon`；本地无数据库配置时使用内存实现。

每次线上请求从 HttpOnly Cookie 或 `X-MMD-Session` 获取会话标识，所有 Product 查询和写入自动附加 `sessionId`。新会话自动写入种子数据。

## HTTP 协议

渲染器默认调用：

```text
POST /api/mmd/meta
POST /api/mmd/query-list
POST /api/mmd/query-one
POST /api/mmd/save
POST /api/mmd/remove
POST /api/mmd/actions/:action
```

另外提供 Product REST 别名，便于 curl 和 OpenAPI 调试。Hono 统一校验输入并映射 `MmdError`。

## 前端

`MmdProvider` 解析环境、Provider 和组件三级配置；内置 HTTP Client、匿名认证、Hash 路由、错误反馈及中英文消息。`FieldRegistry` 按场景解析字段组件，`ActionRegistry` 执行内置或自定义操作，`MmdRenderer` 加载元数据后生成列表、详情和表单。

官网使用 Next.js 静态导出，由 Cloudflare Workers Static Assets 托管；API 为独立 Worker，因此生产环境显式设置 API 地址和跨域 Cookie。

## 验证

- 单元测试：contracts/engine/renderer/API/网站配置。
- 类型检查：全部 workspace。
- 构建：Next.js 静态导出与 Wrangler dry-run。
- 集成测试：Neon 的查询、保存、Action 与删除。
- 浏览器测试：中英文切换、CRUD、自定义字段、自定义操作和请求日志。
- 线上测试：健康检查、OpenAPI、官网资源与两个自定义域名。

## 风险

- npm 名称可能被抢注：发布前重新查询并先发 beta。
- 公共 Demo 被滥用：会话隔离、限制写入范围，后续增加速率限制和过期清理。
- 静态站与 API 跨域：限制 CORS 来源并使用 `credentials: "include"`。
- Neon 冷启动：复用 Worker 友好的 Neon Adapter，持续监控首请求耗时。
