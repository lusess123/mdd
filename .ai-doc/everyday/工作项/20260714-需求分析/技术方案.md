# 技术方案

## 模块边界

```text
mmd-contracts
    ↑                 ↑
mmd-engine       mmd-renderer
    ↑                 ↑
MmdDataAdapter   MMD HTTP API
    ↑                 ↑
Prisma + Neon       Hono
```

- `mmd-contracts` 仅包含可序列化协议和兼容别名。
- `mmd-engine` 校验模型、字段、过滤条件和写入内容，不持有数据库连接。
- `mmd-renderer` 根据元数据渲染 React 界面，通过 `MmdClient` 访问服务端。
- Demo API 负责 Hono 路由、Zod 校验、运行时创建和错误映射。

## 数据访问

`MmdDataAdapter` 只定义 `findMany`、`count`、`findOne`、`create`、`update`、`remove`。Neon 实现使用 Prisma Client + `@prisma/adapter-neon`；未配置数据库时使用内存 Adapter。

生产环境将 Cloudflare 来源 IP 转为哈希会话 ID，不写入原始 IP；本地 Neon 模式使用 Cookie 或 `X-MMD-Session`。所有 Product 查询和写入均限定当前会话，新会话写入种子数据。

Cloudflare 按来源 IP 统一限制每分钟 120 次 API 请求。Neon Trigger 原子维护记录计数，每个会话最多保留 50 条 Product。

## HTTP 协议

渲染器默认调用：

```text
POST /api/mmd/meta
POST /api/mmd/query-list
POST /api/mmd/query-one
POST /api/mmd/save
POST /api/mmd/remove
POST /api/mmd/actions/:action
```

另外提供 Product REST 别名，便于 curl 和 OpenAPI 调试。Hono 统一校验输入并映射 `MmdError`。

## 前端

`MmdProvider` 内置 HTTP Client、匿名认证、Hash 路由、错误反馈和中英文消息，并允许覆盖 API、认证、路由、错误处理及文案。`FieldRegistry` 和 `ActionRegistry` 负责扩展，`MmdRenderer` 根据元数据生成列表、详情和表单。

官网使用 Next.js 静态导出：外壳保持手绘漫画风，首页和 Playground 内部运行真实、标准 Ant Design 风格的 `MmdRenderer`。公开文档只介绍 MMD 库的安装、配置、扩展和 API 协议；Demo 站点的部署说明仅保留在仓库维护文档中。线上显式配置 API 地址和 `credentials: "include"`。

## 部署

生产只通过 GitHub Actions 发布。`main` 分支更新后依次执行仓库验证、Neon migration、Hono Worker 部署与验证，最后部署 Next.js 静态网站。

- 官网：`mmd.zyking.xyz`
- API：`mmd-api.zyking.xyz`
- API 文档：`mmd-api.zyking.xyz/docs`

## 验证

- 单元测试：contracts/engine/renderer/API/网站配置。
- 类型检查：全部 workspace。
- 构建：Next.js 静态导出与 Wrangler dry-run。
- 集成测试：Neon 的查询、保存、Action 与删除。
- 浏览器测试：中英文切换、CRUD、自定义字段、自定义操作和请求日志。
- 线上测试：健康检查、OpenAPI、官网资源与两个自定义域名。

## 风险

- npm 名称可能被抢注：发布前重新查询并先发 beta。
- 公共 Demo 被滥用：已实现会话隔离、每 IP 限流和 Neon 原子配额；上线后持续观察存储增长。
- 静态站与 API 跨域：限制 CORS 来源并使用 `credentials: "include"`。
- Neon 冷启动：复用 Worker 友好的 Neon Adapter，持续监控首请求耗时。
